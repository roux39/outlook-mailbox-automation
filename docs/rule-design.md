# 규칙 설계서

## 1. 요구사항

| 번호 | 요구사항 | 결정 |
|---|---|---|
| R1 | 비슷한 요청을 한곳에서 보고 싶다 | 폴더 이동 대신 **범주(태그)** 사용. 메일은 원래 폴더에 남기고 범주로 모아 봄 |
| R2 | 새 메일도 자동으로 분류되어야 한다 | 받은 메일 규칙으로 제목 키워드를 검사해 범주 지정 |
| R3 | 국내 공급사 메일과 사내 메일 모두 분류 | 국내 공급사 폴더 + 받은 편지함(사내 메일)을 분류 대상으로 함 |
| R4 | 해외 메일은 읽음 처리, 단 나에게 직접 온 메일은 제외 | "받는 사람 줄에 내 이름이 없는 경우" 조건 사용 (CC만 된 메일은 읽음) |
| R5 | 2개월 이전 메일은 읽음 처리 | 기준일 이전 읽지 않은 메일을 일괄 읽음 처리 |
| R6 | 아무것도 지우지 않는다 | 삭제·이동 작업은 쓰지 않음. 기존 범주도 그대로 유지 |

## 2. 범주 설계

처음에는 6개 범주로 시작했고, 실제 메일을 보며 8개로 다듬었습니다.

| 변경 | 이유 |
|---|---|
| "물류·통관" 범주 삭제 | 선적·통관은 해외 업무라 국내 구매 담당에게 필요 없음 |
| "소요량·Forecast" 추가 | 영업팀이 보내는 수요·Forecast 메일이 납기 문의와 섞여 있었음 |
| "입고처리·거래명세서" 분리 | 거래명세서는 물류 처리와 같은 흐름이라 하나로 묶음 |
| 인수증, 출고요청, DC 입고 키워드 제외 | 실제 업무에서 찾아볼 일이 없는 알림성 메일이 많이 걸림 |
| 세금계산서는 "정산·세금계산서"로 따로 둠 | 거래명세서(입고 확인)와 세금계산서(대금 정산)는 확인 시점이 다름 |

## 3. 키워드 선정 원칙

- **오탐이 많은 짧은 영어 단어는 뺍니다.**
  - `PO`: Report, Import, Position 같은 단어 안에서도 걸림 → `PO No`, `PO#`, `Purchase Order`로 대체
  - `ETA`: Details, Metal 같은 단어 안에서도 걸림 → 한국어 표현(`입고 일정`, `납기`)으로 대체
- **본문이 아닌 제목만 봅니다.** 본문은 회신이 쌓이며 여러 주제가 섞이기 때문입니다.
- **한 메일에 범주가 여러 개 붙는 것을 허용합니다.** 하나만 고르게 하면 놓치는 요청이 생깁니다.
- 알려진 한계: `COO`는 "Cooperation" 같은 단어에도 걸릴 수 있어 사용하며 확인합니다.

## 4. 규칙 순서와 동작

Outlook 규칙은 위에서 아래로 실행되고, "더 이상 규칙 수행 중지"가 켜진 규칙을 만나면 거기서 멈춥니다.

| 순서 | 규칙 | 규칙 처리 중지 |
|---|---|---|
| 1 | 해외 수입·통관 메일 자동 읽음 | 끔 |
| 2–9 | 범주 분류 규칙 8개 | 끔 |
| 10 | 해외 발신자 자동 읽음 + 범주 지우기 | 끔 |
| 11~ | 기존 업체별 폴더 이동 규칙 | 해외: 켬 / 국내: 끔 |

- 새 규칙을 추가하면 목록 맨 위에 생깁니다. 그래서 분류 규칙이 폴더 이동보다 먼저 실행되고, 메일은 범주가 붙은 채로 원래 폴더로 이동합니다.
- 해외 메일도 분류 규칙을 먼저 지나가기 때문에, 10번 규칙에서 범주를 다시 지워 해외 메일이 범주 목록에 섞이지 않게 했습니다.

## 5. 해외 발신자 식별

처음에는 이메일 도메인으로 해외 메일을 구분하려 했지만, 해외 계열사 담당자는 **같은 회사 도메인**을 쓰고 있어 도메인만으로는 구분할 수 없었습니다.

- 기존 해외 폴더 이동 규칙(약 240개)에서 발신자를 모았습니다.
- 외부 공급사·포워더는 **도메인**으로, 해외 계열사 담당자는 **개별 주소**로 등록했습니다.
- 최근에 메일이 없어 주소를 확인할 수 없는 일부 발신자는 빠졌습니다. 이런 메일은 원래 폴더로는 가지만 읽지 않음으로 남으므로, 발견하면 목록에 추가합니다.

## 6. 시행착오

| 문제 | 원인 | 해결 |
|---|---|---|
| "나에게 직접 온 메일만" 남겼는데 CC 메일도 남음 | Outlook의 "나에게 보냄" 필터는 받는 사람과 참조를 모두 포함 | `to:` 검색으로 받는 사람 줄만 확인하는 방식으로 변경 |
| 일괄 읽음 처리 후 일부 메일이 다시 읽지 않음으로 복원되지 않음 | 폴더 전체 읽음 처리가 서버에서 끝나기 전에 복원 작업이 실행됨 | 처리 완료를 확인한 뒤 복원하고, 결과를 다시 조회해 검증 |
| 한 번에 75건까지만 선택됨 | Outlook 웹의 선택 한도 | 검색 → 선택 → 처리를 반복 |
| 대화 묶음 보기에서 오래된 메일만 처리할 수 없음 | 대화 단위로 선택되어 최근 회신까지 함께 처리됨 | 작업 중에만 "메시지 그룹화 안 함"으로 바꾸고, 끝난 뒤 원래 보기로 복구 |
| 기존 규칙이 모두 "규칙 처리 중지" 상태 | 폴더 이동 규칙이 315개 모두 처리를 멈추게 설정되어 있었음 | 국내 공급사 규칙 51개 + 세금계산서 규칙 5개의 설정을 변경 |

## 7. 운영 방법

- 새 메일은 자동으로 분류됩니다. 키워드가 없는 제목의 메일만 직접 범주를 붙입니다.
- 같은 유형인데 자꾸 빠지는 메일이 있으면 그 제목의 단어를 해당 규칙에 추가합니다.
- 다른 범주에 잘못 붙는 메일이 있으면 원인 키워드를 더 구체적인 표현으로 바꿉니다.
